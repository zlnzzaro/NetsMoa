## 1. 문제 정의

1. 종프나 교외 공모전에 나가고 싶은데 **같이 할 사람을 어디서 찾아야 할지 모르겠다.**
2. 모집글을 봐도 **어떤 역할이 비어 있고 내가 들어갈 만한 팀인지** 한눈에 파악하기 어렵다.

컴학 학생들이 공지방이나 인스타그램에서 편하게 대화하고 팀원을 구할 만한 공간이 부족하다. 결국 아는 사람한테 먼저 물어보게 되는데, 아는 사람이 적으면 팀 구하는 것부터 막막하다. ("나만 아싸일 리 없어!")

### 해결 방법
**넷츠모아**는 게임 파티를 모집하듯이 `프론트엔드 2명 / 백엔드 1명 / 디자인 1명`처럼 **필요한 역할과 빈자리를 먼저 보여 주는** 모집 플랫폼이다.

- 작성자는 역할별 인원과 원하는 기술스택만 적으면 모집글이 완성된다.
- 지원자는 빈자리를 골라 지원하고, 내 기술스택과 맞는 자리는 따로 표시된다.
- 작성자와 지원자가 1:1로 면담한 뒤 합류를 정하고, 정원이 차면 모집이 알아서 닫힌다.
- 팀이 꾸려지면 팀원에게만 팀 채팅(카카오톡·디스코드) 링크가 열린다.
- 학교 이메일(@knu.ac.kr) 인증을 거친 학생만 가입할 수 있다.

## 2. 구현한 기능

### 회원
- **학교 이메일 회원가입**: `@knu.ac.kr`만 가입 가능 (화면과 DB 트리거에서 이중으로 검사)
- **메일 인증**: 가입하면 인증 메일 발송 → 링크를 누르면 자동 로그인 후 홈으로 이동. 인증 메일 다시 보내기, 만료 링크 안내 포함
- **로그인 / 로그아웃**, 로그인이 필요한 동작은 로그인 후 원래 화면으로 복귀
- **내 정보**: 닉네임(중복 불가), 한 줄 소개, 기술스택(최대 10개), 희망 역할, 프로필 사진, 비밀번호 변경
- 학번과 이메일은 **본인만** 볼 수 있음

### 모집글
- **모집글 작성**: 분류(공모전 / 캡스톤 / 스터디 / 사이드 프로젝트), 소개, 기술스택, 마감일, 팀 채팅 링크
- **역할별 모집 인원**: 프론트엔드·백엔드·AI·디자인·발표·기타 중 골라 인원과 원하는 기술스택 지정. 첫 번째 역할은 작성자 본인 자리
- **게시판**: 검색(제목·기술스택·소개), 분류 탭, "빈자리가 있는 역할" 필터, 10개씩 더 보기
- **홈**: 서비스 소개, 스크롤하면 나타나는 기능 소개, 넘겨 보는 모집글 카드
- **빈자리 시각화**: 역할마다 찬 자리 / 빈 자리를 칸으로 표시, 팀 완성도(%) 표시
- **기술스택 매칭**: 내 기술스택과 겹치는 역할·기술에 "매칭" 표시

### 지원 · 면담 · 합류
- **역할 지원**: 원하는 역할을 골라 한 줄 소개와 함께 지원, 지원 취소 후 재지원 가능
- **지원 상태 5단계**: 검토 대기 → 면담 중 → 합류 확정 / 선발 종료 / 신청 취소
- **1:1 면담 채팅**: 작성자와 지원자 두 사람만 보는 **실시간** 채팅 (Supabase Realtime)
- **지원자 관리(작성자 전용)**: 역할별 지원자 목록, 면담하기 / 합류 확정 / 선발 종료 / 되돌리기
- **자동 마감**
  - 역할 정원이 차면 그 역할의 남은 지원자는 자동으로 선발 종료
  - 모든 역할이 차면 모집글이 자동으로 마감
  - 되돌리기를 하면 다시 검토 대기로 바뀌고 모집이 다시 열림

### 팀
- **팀 화면**: 합류가 확정된 팀원 목록(팀장 표시)
- **팀 채팅 링크**: 작성자와 확정된 팀원에게만 공개
- **내 활동**: 내가 쓴 모집글, 내 지원 현황, 내가 속한 팀을 한곳에서 확인

### 보안
- 모든 테이블에 **RLS(Row Level Security)** 적용: 지원서·면담 메시지는 당사자만, 팀 채팅 링크는 팀원만 조회
- 테이블 직접 쓰기는 막고, 모든 쓰기는 **권한을 검사하는 DB 함수(RPC)**로만 처리

## 3. 기술 스택

React 19 · React Router 7 · Vite 8 · JavaScript · CSS · Supabase (PostgreSQL · RLS · RPC · Auth · Realtime) · Gmail SMTP · Vercel · Git/GitHub · PGlite · oxlint

| 분류 | 기술 | 사용 용도 |
| --- | --- | --- |
| Frontend | **React 19 · React Router 7** | 컴포넌트 기반 화면과 페이지 이동 |
| | **Vite 8** | 개발 서버와 프로덕션 빌드 |
| | JavaScript · CSS | 화면 로직과 스타일 (CSS 프레임워크 없이 직접 작성) |
| Backend (BaaS) | **Supabase** | 별도 서버 없이 DB·인증·실시간 기능 제공 |
| | **PostgreSQL** | 프로필, 모집글, 역할, 지원서, 면담 메시지, 팀 채팅 링크 저장 |
| | **RLS · RPC(PL/pgSQL) · Trigger** | 행 단위 권한, 지원·확정·자동 마감 로직, 학교 이메일 가입 제한 |
| | **Supabase Auth** | 이메일 + 비밀번호 로그인, 이메일 인증 |
| | **Supabase Realtime** | 1:1 면담 채팅 실시간 전달 |
| | Gmail SMTP | 인증 메일 발송 |
| 배포 | **Vercel** | 프론트엔드 배포 (https://netsmoa.vercel.app) |
| 개발 도구 | Git · GitHub | 브랜치·PR 기반 협업 |
| | PGlite | 로컬에서 DB 스키마·권한·흐름 테스트 |
| | oxlint | 코드 검사 |

### 구조
```
브라우저 (React SPA, Vercel)
   │  supabase-js
   ▼
Supabase ── Auth (학교 이메일 인증)
         ├─ PostgreSQL  읽기: RLS 걸린 테이블 조회 / 쓰기: 권한 검사 RPC
         └─ Realtime    면담 메시지 실시간 전달
```

```
frontend/              React 앱
  src/api/             데이터 호출 (remote: Supabase, mock: 체험용 가짜 데이터)
  src/pages/           화면 (홈, 게시판, 모집글 상세, 지원자 관리, 팀, 내 활동, 내 정보, 로그인)
backend/supabase/      DB
  schema.sql           테이블, RLS, RPC 함수, 트리거, Realtime 설정
  school_email.sql     학교 이메일 가입 제한
  seed.sql             시연용 계정과 모집글
```

### 로컬에서 실행하기
1. Supabase 설정: [`backend/supabase/README.md`](backend/supabase/README.md) 순서대로 진행
2. `frontend/.env.local` 작성 (`frontend/.env.example` 참고)
3. 실행
   ```bash
   cd frontend
   npm install
   npm run dev
   ```
   `.env.local`이 없으면 가짜 데이터로 돌아가는 **체험 모드**로 실행됩니다.

## 4. 역할 분담

### 백엔드 1 — 모집글
- 모집글 등록 구현. 제목, 설명, 분류와 함께 `백엔드 1명`, `발표 1명`처럼 역할별 모집 인원을 저장.
- 모집글 목록에 글 ID와 모집 역할을 추가하고, 글 하나를 열었을 때 상세 내용을 가져오는 기능 구현.
- 지원 기능에서 사용할 모집글 ID와 모집 역할 ID를 백엔드 2와 맞춤.
- 글 등록·조회 연결 후 분류·역할 필터, 관심 분야 피드, 모집 마감 구현.

### 백엔드 2 — 로그인·지원·승인
- 로그인과 프로필 구현. 글을 올리거나 지원할 때 서버에서 로그인한 사용자 확인.
- 역할별 지원, 내 지원 현황 조회, 글 작성자의 지원자 목록 조회 및 승인·거절 구현. 역할별 정원을 넘겨 승인되지 않도록 처리.
- 팀 채팅방 링크 저장 및 조회 구현. 글 작성자가 링크를 등록하고, 작성자와 승인된 팀원만 볼 수 있게 함.

### 프론트엔드 2명 — 웹 화면 및 연동
- 로그인·프로필, 모집글 목록·상세·등록, 지원서 작성, 내 지원 현황, 작성자용 지원자 관리 화면 구현.
- 모집글 상세에서 원하는 역할을 골라 지원할 수 있게 연결하고, 승인된 사용자에게 팀 채팅방 링크를 표시.
- 글 등록 → 역할 지원 → 작성자 승인 → 팀 채팅방 링크 확인까지 실제로 이어지는지 백엔드와 같이 테스트.
